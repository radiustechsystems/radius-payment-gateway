# Conformance vectors

These files are the contract every enforcement point must pass, for the format versions it
accepts: `agent.json` is `radius.policy/0.2`, every other file `radius.policy/0.1`. The Rust
reference evaluator runs them in `tests/vectors.rs`, and the TypeScript evaluator
(`packages/policy`) in `packages/policy/test/vectors.test.ts`. Expectations are written by hand,
never generated by an evaluator.

Each file is one compiled policy and the cases run against it:

```jsonc
{
  "description": "What the file covers",
  "policy": { /* a compiled policy, or null for "no policy fetched yet" */ },
  "cases": [
    {
      "name": "the first request over the free quota must pay",
      "request": {
        "method": "GET",
        "path": "/tx/0xabc",
        "client_ip": "198.51.100.7",                        // optional
        "caller": { "id": "acct_42" },                      // optional: the identify hook
        "agent": { "category": "search_engine_crawler",     // optional, 0.2: what the gate verified
                   "signature_agent": "https://radiustech.xyz" },
        "now": 1760000000                                   // Unix seconds
      },
      // Optional: resolve client_ip per defaults.client_ip instead of giving it.
      "transport": { "remote_addr": "203.0.113.50", "headers": { "cf-connecting-ip": "10.1.2.3" } },
      "no_policy": "deny",      // only with "policy": null: the configured failure.no_policy
      "counts": [21, 21],       // each counter's value after adding this request, or
      "counter_error": true,    // every counter failed
      "expected": {
        // Present when the selected rule has a rate limit or a free quota: what to count (the rate
        // limit's counter, then the free quota's), then decide.
        "counted": [
          { "rule": "tx-lookup/freemium", "limit": "rate_limit", "key": "<uid>:rate:<now / 60>:ip:198.51.100.7", "reset_s": 40 },
          { "rule": "tx-lookup/freemium", "limit": "free_quota", "key": "<uid>:free:<now / 300>:ip:198.51.100.7", "reset_s": 100 }
        ],
        "decision": {
          "rule": "tx-lookup/freemium",          // null when no rule matched
          "type": "payment_required",     // allow | deny | payment_required
          "price": "0.001", "description": "…", "accepts": [ /* the action's accepts */ ],
          "status": 429, "code": "rate_limited",  // deny only
          "headers": { "RateLimit-Limit": "60", "RateLimit-Remaining": "39", "RateLimit-Reset": "40" }
        }
      }
    }
  ]
}
```

## Semantics the vectors pin down

- The first rule whose `match` holds is the only rule applied. Match fields are ANDed and list
  values ORed; an empty match matches everything. An endpoint matches on method (an empty list is
  any method) and path (`:name` is one segment, a trailing `*` the path and below; a query string
  and one trailing `/` are ignored). IPv4-mapped IPv6 addresses and ranges (`::ffff:192.0.2.0/120`)
  compare as IPv4, so a mapped address matches an IPv4 range and an IPv4 address a mapped range.
- `match.agent` (`agent.json`, 0.2) holds when every field it lists holds: the request's verified
  `category` is in `category`, and its verified `signature_agent` origin is in `signature_agent`.
  A field the request doesn't have never matches.
- Overlapping endpoints (`overlapping_endpoints*.json`): a request is governed by the most
  specific endpoint it matches (a literal segment beats `:name`, `:name` beats a trailing `*`;
  the path decides before methods), whatever the slugs, and when none of that endpoint's rules
  holds it gets `defaults.unmatched` from `<slug>/_unmatched`, never a less specific endpoint's
  rule. The compiler expresses this as rule order, so evaluators need nothing beyond first-match.
  The authored policies and endpoints these files compile from are in
  `tests/fixtures/vector-sources/`, outside this directory: `tests/vectors.rs` checks the compiler
  emits exactly each file's `policy` (rule uids aside), so they pin the compiler's order as well.
- A rule without a `rate_limit` or `free_quota` decides at once. Otherwise the request is counted
  once per limit, the rate limit first, on `<uid>:<rate|free>:<window index>:<key>`, where the
  window index is `floor(now / window_s)` and the key is `ip:<address>` for IPv4 (IPv4-mapped
  addresses included), `ip:<network>/64` for IPv6 (`ip:2001:db8::/64`), `ip:unknown` without
  one, `caller:<id>` (falling back to the IP key), `global`, or for `agent` (`agent.json`)
  `agent:sig:<origin>`, else `agent:cat:<category>`, else the IP key. `reset_s` is
  `window_s - now % window_s`. Every request that reaches the rule counts against each limit.
- A rate limit count above its `quota` denies with 429 `rate_limited`. Otherwise a free quota
  count up to its `quota` allows; above it, or without a free quota, the action applies.
- With `headers.ratelimit`, counted decisions carry `RateLimit-Limit`, `RateLimit-Remaining`
  (never below 0) and `RateLimit-Reset`, for the rate limit when the rule has one and else for
  the free quota. With `headers.retry_after`, denials carry `Retry-After: <reset_s>` of the limit
  that decided: the rate limit's for a 429, the free quota's for a deny action past it. A failed
  counter adds no headers.
- `failure.counter_error`: `within` reads a failed counter as within its limit (not rate limited,
  allowed by the free quota), `over` as beyond it (rate limited, or the action applies).
- No match: `defaults.unmatched` (`deny` is 403 `no_matching_rule`). No policy ever fetched:
  `no_policy` (`deny` is 503 `policy_unavailable`).
- `defaults.client_ip`: `remote_addr` is the connection's address; `{ header }` is the first
  comma-separated entry in that header, and no address without it. An entry may carry a port
  and IPv6 brackets: `203.0.113.5:4711`, `[2001:db8::1]` and `[2001:db8::1]:443` are addresses.
